# 上游报错换渠道的 JSON 规则

适用于包含此功能的版本。使用超级管理员登录态，通过现有 `PUT /api/option/` 接口保存，`GET /api/option/` 可读回。`value` 是 JSON 数组的文本，示例中的渠道编号仅为占位，不代表线上规则：

```json
{
  "key": "ChannelRetryPolicy",
  "value": "[{\"channel_id\":123,\"status\":429,\"error_code\":\"upstream_busy\",\"action\":\"retry\"}]"
}
```

- 可填 `channel_id`（报错渠道的正整数编号）、`status`（400 到 599）、`error_code`（忽略大小写精确匹配）和 `message_contains`（忽略大小写的子串匹配）。至少填 `status`、`error_code` 或 `message_contains` 之一；同一条规则的条件必须同时满足，从上往下取第一条命中。
- `action` 必填：`retry` 交给原有串行重试和选路逻辑，`stop` 不再尝试。规则不指定备用渠道，不扩大原有重试预算；未命中继续用原有策略。
- 默认 `[]`，清空也填 `[]`。合法保存后本进程立即使用，重启后从数据库读取；其他实例通过原有配置同步刷新。无效配置不会覆盖已保存的配置。上限 128 条规则、64 KiB。
- 不覆盖客户端取消、指定渠道、禁止换渠道的亲和配置、已提交响应、既有专用超时或流错误重试逻辑。此配置不启动并行备用，不更改超时或计费逻辑。串行重试也不意味着上游一定只计费一次。
